# Playbook

Общие правила для всех проектов владельца, одинаковые для любого агента (Claude Code, Codex, Cursor, Copilot и других). Своих правил у проектов остаётся только то, что касается их самих.

## Что здесь

- `rules.md` — общие правила.
- `procedures/` — процедуры по шагам: подготовить PR, «кря» в Telegram, ящик `/quack`, новый тред, журнал сессий (необязательный).
- `templates/` — стартовые файлы проекта.
- `init.sh` — завести новый проект из шаблонов.
- `scripts/sync-rules.sh` — синхронизация и проверка правил в репе проекта.

## Как это устроено в репе проекта

- `AGENTS.md` — инструкции для всех агентов. Сверху название и пара строк о проекте, затем между метками `<!-- playbook:begin … -->` и `<!-- playbook:end -->` копия `rules.md` (в метке записан коммит playbook, из которого она взята), а под блоком раздел «Проект»: устройство, команды, параметры для общих правил и правила самого проекта.
- Необязательные процедуры включаются строкой в разделе «Проект». Сейчас такая одна — журнал сессий: «Журнал сессий: ведём, ветка `<имя>`». Строки нет — журнал не пишут.
- `CLAUDE.md` — одна строка `@AGENTS.md`. Claude Code сам `AGENTS.md` не читает, а так подключает его целиком ([документация](https://code.claude.com/docs/en/memory)).
- `docs/playbook/` — копия `procedures/`.
- `make sync-rules` — обновить блок и `docs/playbook/` из клона playbook рядом с проектом (по умолчанию `../playbook`).
- `make check-rules` и workflow `.github/workflows/rules.yml` — CI падает, если блок или процедуры поправили руками, и предупреждает (не падает), если в playbook появились правила новее.

Почему копия, а не ссылка на playbook: Codex и часть других агентов не умеют подключать файл из `AGENTS.md` ссылкой, им нужен текст в самом файле.

## Новый проект

Проект заводит агент в собственном проекте новой репы, первым PR.

### Что делает владелец

1. Создаёт пустую репу для проекта на GitHub.
2. Подключает к проекту (в Claude — в настройках проекта, раздел с репозиториями) новую репу и репу playbook.
3. Пишет агенту в этом проекте:

   > Заведи проект по playbook: README playbook, раздел «Новый проект», часть «Что делает агент». Проект: <пара строк, что это и зачем>.

4. Проверяет PR агента и мёрджит его.
5. Пишет короткую инструкцию проекта (в Claude — в настройках проекта): агент предложит текст в PR.

### Что делает агент

1. Находит клон playbook рядом с репой проекта (`../playbook`). Если его нет, клонирует его туда сам или просит владельца подключить репу к проекту.
2. Создаёт ветку по общим правилам и запускает `../playbook/init.sh . "<Название проекта>"`. Скрипт копирует шаблоны, не трогая существующие файлы, и сразу вклеивает общие правила (`make sync-rules`).
3. Заполняет раздел «Проект» в `AGENTS.md` и `docs/stack.md`, `docs/roadmap.md` по описанию владельца. Чего не знает (ключ проекта, бот, ящик `/quack`, журнал), спрашивает у владельца, а не придумывает.
4. Открывает PR по `docs/playbook/prepare-pr.md`. В описании PR — готовый короткий текст инструкции проекта для владельца.

## Перевести существующий проект

Перевод делает агент в собственном проекте той репы, одним PR. Каждый проект переводится отдельно.

### Что делает владелец

1. Подключает репу playbook к этому проекту (в Claude — в настройках проекта, раздел с репозиториями), чтобы агент видел её рядом с репой проекта.
2. Пишет агенту в этом проекте:

   > Переведи проект на общие правила из playbook: README playbook, раздел «Перевести существующий проект», часть «Что делает агент».

3. Проверяет PR агента и мёрджит его.
4. После мёрджа заменяет инструкцию проекта (в Claude — в настройках проекта) коротким текстом, который агент предложил в PR.

### Что делает агент

1. Находит клон playbook рядом с репой проекта (`../playbook`). Если его нет, клонирует его туда сам или просит владельца подключить репу к проекту.
2. Создаёт ветку по общим правилам и `AGENTS.md` из `templates/AGENTS.md`.
3. Переносит в раздел «Проект» всё своё, что относится только к этому проекту: из старого `CLAUDE.md` и из инструкции проекта (у кого `CLAUDE.md` нет — только из инструкции). Общие правила, которые уже есть в `rules.md`, не переносит. Заполняет параметры: ключ проекта, автор коммитов, бот, ящик `/quack`, адресат «кря», хелпер тестов, внешние сервисы. Если проект ведёт журнал, добавляет строку «Журнал сессий: ведём, ветка …» с нынешней веткой журнала.
4. Заменяет `CLAUDE.md` одной строкой `@AGENTS.md`.
5. Добавляет в `Makefile` цели `sync-rules` и `check-rules` из `templates/Makefile`, а в `.github/workflows/` — `templates/.github/workflows/rules.yml`.
6. Запускает `make sync-rules`, затем `make check-rules`.
7. Если есть скиллы `.claude/skills/prepare-pr` и `send-to-group`, сводит их к ссылке на `docs/playbook/`.
8. Открывает PR по `docs/playbook/prepare-pr.md`. В описании PR — что из старых правил куда переехало, какие правила проекта расходились с общими и чем их заменили, и готовый короткий текст новой инструкции проекта для владельца.

## Поменять общие правила

1. PR в playbook с правкой `rules.md` или `procedures/`. Перед PR — `make lint` и `make test`, если менялись скрипты.
2. После мёрджа в каждом проекте: `git -C ../playbook pull`, `make sync-rules`, отдельный PR.

При правке помни:

- Репа публичная: никаких секретов, имён, ников и других личных данных, названий и подробностей конкретных проектов. Всё конкретное — в разделе «Проект» самих проектов.
- `rules.md` вклеивается в `AGENTS.md` каждого проекта, а Codex читает не больше 32 КиБ инструкций на все `AGENTS.md` вместе. Поэтому `rules.md` держим коротким, подробности — в процедурах.
- Правило, которое касается одного проекта, сюда не кладём: ему место в разделе «Проект» того проекта.
- Если после правки проектам нужно что-то сделать руками (новый параметр в разделе проекта, новый файл), напиши это в описании PR.
- Своих `AGENTS.md`, `CLAUDE.md` и `docs/` у playbook нет: агент открывает эту репу только для правки правил, и ему хватает этого README.

## Другие агенты

- Codex, Cursor, GitHub Copilot (coding agent) читают `AGENTS.md` сами.
- Gemini CLI по умолчанию читает `GEMINI.md`; чтобы читал `AGENTS.md`, нужна настройка `context.fileName` в `settings.json`.
- Codex читает не больше 32 КиБ инструкций на все `AGENTS.md` вместе.
