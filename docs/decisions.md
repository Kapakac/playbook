# Принятые решения

Короткий список решений владельца, которых нет в коде, `roadmap.md` и `stack.md`, или которые там легко пропустить. Новое решение дописывается сюда в том же PR, где оно появилось, новые сверху внутри раздела. Решение не удаляется, а помечается «отменено» с датой.

## Устройство

- 2026-10-30: общие правила для всех проектов, независимые от агента, лежат в репе `playbook`: `rules.md`, процедуры в `procedures/`, шаблоны и `init.sh`. В каждой репе проекта — `AGENTS.md` с общим блоком между метками, `CLAUDE.md` = `@AGENTS.md`, `make sync-rules` и проверка в CI. Это решение новее разбора «Общие правила для всех проектов» (там предлагалась репа `dev-rules` с общим `CLAUDE.md`, подключаемая к Claude-проектам) и заменяет его. Почему: одни и те же правила лежали копиями в инструкциях нескольких проектов и уже начали расходиться; `AGENTS.md` читают и другие агенты.
- 2026-10-30: блок в `AGENTS.md` — полная копия `rules.md`, а не ссылка: Codex не подключает файлы ссылкой. В метке записан коммит playbook. CI проекта падает, если блок или `docs/playbook/` поправили руками, и только предупреждает, если в playbook есть правила новее: иначе любое изменение правил ломало бы CI всех открытых PR во всех проектах.
- 2026-10-30: процедуры копируются в репу проекта (`docs/playbook/`), а не читаются из playbook: агент проекта может не иметь доступа к клону playbook.
- 2026-10-30: `sync-rules.sh` сам ничего не удаляет: файлы в `docs/playbook/`, которых больше нет в playbook, он только показывает.
- 2026-10-30: репа сейчас публичная, поэтому CI проектов клонирует её без токена. Следствие: никаких секретов, имён и личных данных, подробностей конкретных проектов. Если сделать её приватной, CI проектов понадобится токен с доступом к ней (решение владельца).

## Общие правила

- 2026-10-30: в playbook нет имён и личного: вместо имени — «владелец», а автор коммитов, репа бота и то, что нельзя показывать другим, — параметры в разделе «Проект» каждого проекта.
- 2026-10-30: журнал сессий — необязательная процедура `procedures/journal.md` (формат, ветка, когда писать). Проект включает её одной строкой в своём разделе под общим блоком: «Журнал сессий: ведём, ветка …». Строки нет — журнал не пишут. Так правило одно на всех, а решение «вести или нет» лежит в каждом проекте. Без журнала итог для нового треда идёт прямо в его первое сообщение.
- 2026-10-30: в `AGENTS.md` проекта раздел «Проект» идёт под общим блоком.
- 2026-10-30: расхождения между копиями правил сведены так. Ящик `/quack` — везде по строке «Просмотрено до №N» в `docs/duck-log.md`. Ветка: если среда агента назначила ветку сама (облачная сессия Claude), работаем в ней, иначе `<тема>-<суффикс>`. Имя ветки журнала — параметр проекта, существующие ветки не переименовываем. Значок — «⚠». Правило проекта важнее общего.
