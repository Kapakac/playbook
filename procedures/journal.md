# Журнал сессий

Необязательная процедура. Журнал ведётся, только если в разделе проекта есть строка вида «Журнал сессий: ведём, ветка `<имя>`». Строки нет — журнал не пишем и файлы передачи туда не кладём.

## Где лежит

- Отдельная ветка из строки проекта. Она никуда не мёрджится, в `main` её не тянуть.
- Записи за день — `journal/ГГГГ-ММ-ДД.md`, границы дня по UTC.
- Файлы передачи между тредами — `journal/handoff/ГГГГ-ММ-ДД-<тема>.md` (`docs/playbook/new-thread.md`).
- Итоги сессий на компьютере владельца — `journal/local/ГГГГ-ММ-ДД-<тема>.md`.
- Описание журнала — `journal/README.md` в той же ветке. Если ветки ещё нет, спроси владельца и после «да» создай её пустой, без кода проекта (`git switch --orphan <имя>`), только с этим README.
- Записи только добавляются: прошлые не удаляются и не переписываются.

## Когда писать

- Запись за прошедший день добавляется один раз: задачей по расписанию, если она настроена в проекте, иначе при первом сообщении владельца на следующий день.
- Сессии на компьютере владельца идут вне проекта в Claude, и задача по расписанию их не видит. Если в такой сессии что-то обсудили, решили или сделали, в конце сессии положи короткий итог в ветку журнала файлом `journal/local/ГГГГ-ММ-ДД-<тема>.md` (разделы как в записи за день). Запись за день учитывает эти файлы.
- Если за день владелец ничего не писал ни в проекте, ни в локальных сессиях, записи за этот день нет.

## Формат записи за день

```
# <день месяц год>

<1–3 строки: главное за день.>

## Обсуждали
Вопросы и ответы.

## Решили
Решения, с пометкой «предварительно», если окончательно не утверждено.

## Сделали
PR (ссылками) и файлы.

## Ждёт владельца
Что осталось за ним на конец дня.
```

Только проверенное, как в общих правилах. Пустой раздел можно пропустить. Если в строке проекта есть дополнительные правила журнала (например, срезы документации), следуй и им.
