# Подготовить PR

Когда задача сделана и пора открыть или обновить pull request.

1. Убедись, что ты на ветке задачи, а не в `main`. Одна задача — одна ветка.
2. Сделай `git fetch origin main` и посмотри `git diff origin/main...HEAD`: в нём должна быть только эта задача. Если есть что-то лишнее, остановись и спроси владельца.
3. Линтеры (команда — в разделе проекта, обычно `make lint`): исправь всё найденное и запускай снова, пока не станет чисто.
4. Тесты (обычно `make test`): исправь падения и запускай снова, пока всё не пройдёт. Если тесты с базой пропустились (например, нет `TEST_DATABASE_URL`), скажи об этом.
5. Если есть новая логика без юнит-тестов, допиши их. Для базы — хелпер из раздела проекта. Внешние сервисы не вызывать, только сохранённые ответы.
6. Сделай ревью своих изменений: ищи ошибки и уязвимости (в Claude Code — команда `/code-review`). Исправь найденное и повтори шаги 3–4.
7. Коммит — по-английски, только описание изменений, без упоминаний агента и служебных строк (Co-Authored-By, Claude-Session и т.п.). Автор — как в общих правилах.
8. Запушь ветку и открой PR: через `gh pr create`, а если `gh` недоступен, — через GitHub-инструменты агента. Заголовок — с ключом задачи, как в общих правилах (`shop-12: корзина`). Описание — по-русски, коротко, по шаблону `.github/pull_request_template.md`: что изменено, что нашло ревью, что исправлено, что не проверено. Без подписей «Generated with …», ссылок на сессию и блоков «Requested by …»: если среда добавила их сама, перечитай описание и убери.
9. Следи за CI (`gh pr checks --watch` или GitHub-инструменты): если упал, исправь и запушь, пока не станет зелёным. Тесты не отключай и не пропускай ради зелёного.
10. Напиши владельцу в чат или тред: ссылку на PR, результаты проверок, открытые вопросы. Комментарии и ревью на GitHub не оставляй.
