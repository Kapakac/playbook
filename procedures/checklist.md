# Сверка со списком playbook

Часть правок playbook требует что-то сделать в каждом проекте руками: завести подраздел, поправить workflow, дописать README. Общий блок `AGENTS.md` обновляется сам, а это — нет. Поэтому агент проекта сам замечает, что список «Что должно быть в проекте» в README playbook поменялся, и предлагает доделать недостающее. Отдельной фразы от владельца для этого не нужно.

## Когда

- В первом сообщении треда или сессии, вместе с проверкой ящика `/quack` (`rules.md`, «Процедуры»), даже если тред начат с конкретной задачи: тогда о недостающем — коротко, в конце первого ответа.
- Перед PR (`prepare-pr.md`, шаг 2), если коммит playbook в метке общего блока поменялся.

## Поменялся ли список

1. Обнови клон playbook (README playbook, раздел «Клон playbook»).
2. Найди в разделе «Проект» `AGENTS.md` строку «Список playbook сверен: `playbook@<коммит>`». Строки нет — список ни разу не сверяли: переходи к сверке.
3. Посмотри `git -C ../playbook diff <коммит> origin/main -- README.md templates/ procedures/no-repo-agent.md`. Если в диффе нет раздела README «Что должно быть в проекте», файлов `templates/` и блока из `no-repo-agent.md`, список не менялся: дальше ничего не делай и ничего не пиши. Если коммита нет в клоне (клон неполный), сначала `git -C ../playbook fetch --depth=500 origin main`; всё равно нет — проходи список целиком.

## Сверка

1. Пройди список «Что должно быть в проекте» по колонке «Как проверить». Если список поменялся, а не сверяется впервые, начни с новых и изменённых пунктов, но проверь все.
2. Всё есть — ничего не пиши владельцу; строку «Список playbook сверен» обнови на текущий коммит playbook в ближайшем PR проекта.
3. Чего-то нет — одно сообщение владельцу: что не так по каждому пункту (одна строка), что агент сделает сам и что нужно от владельца руками (настройки репы, бот), и вопрос «Доделать одним PR?» с рекомендуемым ответом «да». Без «да» ничего не доделывай и не добавляй в чужие PR. Ответ «нет» или «позже» действует до конца треда; в новом треде, пока недостающее не доделано, агент снова напомнит одним сообщением.
4. На «да» — как в README playbook, «Что должно быть в проекте», «Что делает агент», шаги 3–4. В том же PR строка «Список playbook сверен» получает текущий коммит playbook.
